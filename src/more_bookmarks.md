# 추가 북마크 만들기

````admonish reset title="진행 상황 초기화" collapsible=true
이 장의 시작으로 되돌리려면 다음 명령을 실행하세요.

```sh
curl https://jj-for-everyone.github.io/reset.sh | bash -s more_bookmarks
cd ~/jj-tutorial/repo
```
````

이제 다시 Alice 차례입니다.

```sh
cd ~/jj-tutorial/repo
```

다음 주 과제가 파이썬의 루프 작성이라는 소문을 들었습니다.
앞서가고 싶은 마음에 Hello World 프로그램에 반복을 추가해 봅니다.

```sh
echo 'for (i = 0; i < 10; i = i + 1):
    print("Hello, world!")' > hello.py
```

안타깝게도 실수가 있었나 봅니다.
`python hello.py`를 실행하면 오류가 발생합니다.

```
  File "/home/user/jj-tutorial/repo/hello.py", line 1
    for (i = 0; i < 10; i = i + 1):
         ^^^^^
SyntaxError: invalid syntax. Maybe you meant '==' or ':=' instead of '='?
```

Alice는 지금 문제를 파고들 시간이 없습니다.
다음 주 강의에서 선생님이 올바른 방법을 설명해 주기를 기다리기로 합니다.
그래도 변경을 그냥 버리고 싶진 않습니다.
나중에 정답과 비교할 수 있도록 실험 결과를 남기려 합니다.
언제나처럼 푸시하기 전에 새 커밋을 만듭니다.

```sh
jj commit -m "WIP: Add for loop (need to fix syntax)"
```

이런 WIP(작업 중) 변경을 바로 main 북마크로 푸시하는 것은 좋지 않습니다.
만약 나중에 Bob이 제출용 tarball을 만들었는데 Alice의 미완성 코드가 포함된다면 큰일 나겠죠.
이를 피하기 위해 Alice는 새 북마크로 커밋을 푸시하기로 합니다.

북마크 이름은 무엇으로 해야 할까요?
`main` 북마크는 강한 관례지만, 추가 북마크는 무엇이든 가능합니다.
변경을 짧게 요약한 `add-for-loop` 같은 이름을 쓸 수도 있습니다.
자신의 이름이나 사용자 이름을 접두사로 붙여(`alice/add-for-loop`) 누가 무엇을 하는지 알기 쉽게 하기도 합니다.
또 어떤 사람은 이슈 트래커의 티켓 번호를 포함시키기도 하죠.
모두 괜찮은 선택이지만, 때로는 _그냥 신경 쓰고 싶지 않을 때_ 도 있습니다.
그럴 때 Jujutsu는 북마크 이름을 자동으로 생성해 빠르게 푸시할 수 있는 옵션을 제공합니다.

```sh
jj git push --change @-
```

자동 생성된 북마크 이름은 `push-` 뒤에 change ID 접두사가 붙습니다.
정보량이 많지는 않지만, 그것이 핵심입니다.
커밋 내용이 중요하고 북마크는 원격으로 보내기 위한 수단일 뿐이니까요.
같은 이유로 북마크 추적도 자동으로 처리되므로 `jj bookmark track`를 따로 실행하지 않아도 됩니다.

`--change` 플래그는 `-c`로 줄일 수 있습니다.
자주 쓰는 플래그 대부분에 이런 축약형이 있습니다.
어떤 Jujutsu 명령이든 `--help`를 붙여 실행하면 사용 가능한 플래그를 살펴볼 수 있습니다. 예: `jj git push --help`.

이제 Alice의 파이썬 루프 실험은 원격에 북마크와 함께 안전하게 보관되면서도 main 브랜치의 작업을 방해하지 않습니다.
좋습니다!
