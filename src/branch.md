Alice와 Bob은 컴퓨터공학 수업에서 팀 프로젝트를 진행하고 있습니다.
과제는 파이썬으로 고전적인 "Hello, world!" 프로그램을 작성하는 것입니다.
둘은 일을 이렇게 나누기로 했습니다.
- Alice는 파이썬 프로그램을 작성합니다.
- Bob은 README에 설명을 추가합니다.

먼저 Alice부터 시작하죠.
그녀가 떠올린 파이썬 프로그램은 다음과 같습니다.

```python
print("Hello, world!")
```

문제없이 작동하겠죠.
이를 `hello.py` 파일에 추가합니다.

```sh
echo 'print("Hello, world!")' > hello.py
```

Alice는 깜짝 놀라 잠시 소셜 미디어를 켜고 아기 오리들과 껴안고 있는 고양이 영상을 찾아 마음을 달랩니다.

힌트대로 먼저 원격에서 데이터를 가져옵니다.

```sh
jj git fetch
```

`fetch`는 새로운 명령으로, 기본적으로 `push`의 반대입니다.
`push`가 로컬 저장소의 북마크와 커밋을 원격으로 보낸다면, `fetch`는 다른 사람이(예: Bob) 다른 컴퓨터에서 푸시한 북마크와 커밋을 내려받습니다.

오!
처음 보는 상황입니다.
버전 히스토리가 두 개의 **브랜치** 로 갈라졌습니다.
이는 흔한 일이며, 서로 독립적으로 작업하도록 해 주는 Jujutsu의 핵심 개념입니다.
다만 아직 이 상황을 처리하는 방법을 배우지 않았습니다.

Jujutsu가 Bob의 업데이트를 모른 채 Alice가 `main` 북마크를 푸시하도록 허용했다면 Bob의 작업이 실수로 지워졌을 겁니다.
원격은 북마크에서 **도달 가능한** 커밋만 남기고 나머지는 삭제할 수 있기 때문입니다.
`main` 북마크가 Alice의 커밋을 가리키면 Bob의 커밋은 더 이상 조상이 아니므로 도달할 수 없습니다.

로그에 `main` 북마크가 **두 번** 등장하며 둘 다 물음표 **`??`** 가 붙어 있는 것에 주목하세요.
이는 Jujutsu가 북마크가 어디를 가리켜야 할지 확신하지 못한다는 뜻입니다.
Alice는 자신의 커밋으로 옮겼지만, 원격에서는 Bob의 커밋으로 옮겨져 있습니다.
Alice가 어디를 가리켜야 할지 결정하면, 명시적으로 그 위치로 이동시키면 됩니다.

```admonish info title="헷갈리는 용어: 북마크와 브랜치"
"북마크"와 "브랜치"는 비슷한 상황에서 자주 사용되어 혼동을 일으키곤 합니다.
둘의 차이를 명확히 정의하고 잠재적인 혼선을 인지해 둡시다.

**북마크** 는 하나의 커밋에 붙어 있는 이름표일 뿐입니다.
그게 전부입니다.

**브랜치** 는 **팁** 으로 정의되며, 그 팁과 **모든 조상 커밋** 을 포함하는 **커밋 집합** 을 의미합니다.

이 두 개념을 조합해 "나는 변경을 `main` 브랜치에 푸시했다" 같은 문장을 만들 수 있습니다.
`main`은 북마크인데 왜 "브랜치"라고 부를까요?
`main` 북마크가 커밋을 가리키고, 그 커밋이 우리가 "main 브랜치"라고 부르는 브랜치의 팁이기 때문입니다.

Git을 주로 사용하는 사람과 이야기할 때는 또 다른 주의가 필요합니다.
Git에서는 두 개념 모두에 대해 항상 **브랜치** 라는 단어만 사용합니다.
"북마크"라는 용어는 존재하지 않습니다.
따라서 Git 사용자가 "브랜치"라고 말할 때 실제 브랜치를 의미할 수도 있고, 단순히 하나의 커밋을 가리키는 이름표를 의미할 수도 있습니다.
```
