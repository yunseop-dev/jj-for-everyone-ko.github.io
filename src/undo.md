# 실수 되돌리기

````admonish reset title="진행 상황 초기화" collapsible=true
이 장의 시작으로 되돌리려면 다음 명령을 실행하세요.

```sh
curl https://jj-for-everyone.github.io/reset.sh | bash -s undo
cd ~/jj-tutorial/repo
```
````

지금까지 배운 것만으로도 많은 일을 할 수 있습니다. 단, 문제가 생기지 않는다면 말이죠.
예를 들어 `jj commit`을 실행한 뒤 급하게 대충 커밋 메시지를 적어 버렸다고 합시다.
그 메시지를 고치고 싶습니다.

지금까지의 기술만으로는 `jj commit` 이후 커밋 설명을 수정할 수 없습니다.
그렇다면 저장소에 가한 변경을 **되돌릴** 수 있다면 어떨까요?
시간을 거슬러 올라가는 셈이죠.
가능합니다. Jujutsu는 커밋 형태로 프로젝트 히스토리를 저장할 뿐 아니라, 저장소에서 수행한 **모든 작업** 의 로그도 함께 보관하기 때문입니다.
이 "작업 로그"를 조회하고 특정 시점으로 되돌리는 저수준 명령도 존재합니다.
하지만 지금은 한 번에 한 단계씩 작업을 되돌리거나 다시 적용하는 고수준 명령만 배우겠습니다.

현재 저장소 상태를 다시 확인해 봅시다.

```sh
cd ~/jj-tutorial/repo
jj log
```

```sh
echo 'print("Hallo, Welt!")' >> hello.py
echo 'print("Bonjour, le monde!")' >> hello.py
```

## `jj undo`로 되돌리기

낙제점 메시지를 바로잡아 봅시다.
앞 장 마지막에 저장소를 main 브랜치 상태로 되돌리기 위해 `jj new main`을 수행했습니다.
그 후 `jj undo`를 실행하면 방금 만든 커밋이 사라지고 이전 상태로 돌아갑니다.

```sh
jj undo
```

`jj undo`는 마지막 작업을 한 단계 되돌립니다.
주의 깊게 보았다면, `jj undo`가 새 커밋이 아닌 "저장소 작업" 전체를 대상으로 한다는 사실을 알 수 있습니다.

### 여러 단계 되돌리기

실수 뒤에 다른 일을 하고, 한참 뒤에야 실수를 깨닫는 경우도 있습니다.
여러 단계를 되돌릴 수 있을까요?
물론입니다. 익숙한 <kbd>Ctrl+Z</kbd>처럼 매번 호출할 때마다 과거로 한 걸음씩 이동합니다.
방금 `jj commit`을 실행했으니 한 번 더 실행하면 그 이전 상태로 돌아갑니다.

```sh
jj undo
```

그 작업은 `jj` 명령이 아니었지만, 그래도 별도의 작업으로 기록됩니다.
Jujutsu는 모든 `jj` 명령 실행 전 파일 변화를 감지하고, 변경이 있으면 별도의 작업(스냅샷)으로 저장합니다.
이 덕분에 파일 변경만 따로 `jj undo` 할 수 있습니다.

다시 한 번 `jj undo`를 실행해 `hello.py`의 변화를 확인해 봅시다.

```py
# hello.py
print("Hello, world!")
print("Hallo, Welt!")
print("Bonjour, le monde!")
```

```sh
jj undo
```

```py
# hello.py
print("Hello, world!")
```

## `jj redo`로 다시 적용하기

방금 되돌린 세 단계는 실제로 실수가 아니었습니다.
다시 적용할 수 있을까요?
그래픽 앱에서라면 "다시 실행" 버튼이나 <kbd>Ctrl+Shift+Z</kbd>를 사용합니다.
Jujutsu에서는 `jj redo`를 실행하면 됩니다.
세 번 실행해 최신 상태로 되돌아가 봅시다.

```sh
jj redo
jj redo
```

## 되돌린 뒤 새 작업을 하면

앞서 작성한 나쁜 커밋 메시지("code improvements")는 이제 `jj undo`와 `jj redo`만으로는 복구할 수 없습니다.
몇 단계 되돌린 뒤 새 작업을 만들면, 되돌린 상태는 숨겨집니다.
일반 그래픽 앱의 일반적인 "되돌리기" 동작과 동일하므로 놀랄 일은 아닐 겁니다.

그래픽 앱과 달리 Jujutsu에는 이러한 숨겨진 상태도 다시 꺼내는 고급 명령이 존재합니다.
이 부분은 나중에 다룹니다.

## 원격 관련 작업은 되돌리지 마세요

북마크를 푸시해 커밋을 원격으로 보내는 작업도 기술적으로는 저장소 작업입니다.
하지만 이런 작업을 되돌리는 것은 거의 항상 나쁜 생각입니다.
원격 상태를 되돌리지 않기 때문입니다.
즉, `jj undo`는 "원격으로 푸시했다"는 사실만 잊어버릴 뿐, 원격은 그대로 남습니다.
이후 fetch나 push를 시도할 때 "conflicted bookmarks", "divergent change IDs" 같은 골치 아픈 오류를 만날 수 있습니다.

이런 오류를 해결할 수 있는 방법은 있지만 지금 설명할 시점은 아닙니다.
그러니 **그냥 하지 마세요**.

만약 실수로 `jj git push`를 되돌렸다 해도 `jj redo`를 실행하면 대부분 문제가 해결됩니다.
앞으로는 원격과 상호작용한 작업을 `jj undo`가 거부하도록 바뀔 수도 있습니다.

## 저장소 작업 히스토리는 원격에 백업되지 않습니다

로컬 저장소를 삭제했더라도 원격이 있다면 큰일은 아닙니다.
다시 클론하면 커밋 히스토리를 모두 되찾을 수 있습니다.
하지만 저장소에서 수행한 작업 히스토리는 로컬에만 존재합니다.
따라서 `jj undo`는 클론한 시점보다 이전으로는 되돌릴 수 없습니다.
