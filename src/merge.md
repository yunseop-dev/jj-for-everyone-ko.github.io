# 머지 커밋 만들기

curl https://jj-for-everyone.github.io/reset.sh | bash -s merge

이제 충분히 준비했으니 두 변경을 결합한 버전을 만들어 봅시다.

이를 달성하는 방법은 사실 두 가지가 있으며, 다른 하나는 나중에 다룹니다.
지금은 **머지 커밋** 을 만들겠습니다.
이름에서 알 수 있듯 머지 커밋은 두 개(또는 그 이상!)의 커밋으로부터 변경을 합칩니다.

지금까지 새 커밋을 만들 때는 `jj commit` 명령을 사용했습니다.
이 명령은 사실 두 가지 작업을 동시에 처리합니다.
방금 작업한 커밋에 설명을 붙이고, 그 위에 새 커밋을 생성합니다.
아쉽게도 머지 커밋은 만들지 못합니다.

새 커밋을 만들기 위한 좀 더 "저수준" 명령으로 `jj new`가 있습니다.
이 명령은 새 커밋만 만들고 설명은 건드리지 않습니다.
중요한 점은 추가 인자로 **부모 목록** 을 받는다는 것입니다.
부모를 두 개 지정하면 머지 커밋을 만들 수 있습니다.

```sh
jj new main@origin @-
```

흥미롭네요!
새 머지 커밋의 두 부모가 커밋 그래프에 뚜렷하게 드러납니다.
이 커밋에 Alice와 Bob의 변경이 모두 포함됐는지 확인해 봅시다.

```sh
cat README.md
cat hello.py
```

Jujutsu는 판단력을 발휘해 변경을 결합하지만, 지나치게 똑똑하지는 않습니다.
프로젝트의 같은 부분을 동시에 수정하면 **충돌** 이 발생합니다.
충돌이 반드시 나쁜 것은 아닙니다.
각 변경이 달성하고자 한 핵심을 유지하도록 수동으로 조합해야 한다는 신호일 뿐입니다.
충돌 해결 방법은 다음 레벨에서 배울 주제입니다.

이제 머지 커밋을 마무리하고 원격으로 보냅시다.

```sh
jj commit -m "Merge code and documentation for hello-world"
jj bookmark move main --to @-
jj git push
```

휴!
꽤나 강렬했습니다.
지금 `jj log`를 실행하면 복잡한 분기와 병합이 기본적으로 숨겨집니다.
필요하다면 `jj log --revisions 'all()'`로 다시 볼 수 있다는 점을 기억하세요.
