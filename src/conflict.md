### 충돌 표식 이해하기

첫 줄과 마지막 줄에 주목합시다.

```
<<<<<<< Conflict 1 of 1
...
>>>>>>> Conflict 1 of 1 ends
```

두 줄은 충돌 구간의 시작과 끝을 나타냅니다.
파일이 큰 경우 대부분의 영역은 문제없이 병합되며, 동일한 줄을 양쪽이 수정했을 때만 충돌이 발생합니다.
충돌된 줄 덩어리는 번호가 매겨진 섹션으로 표시되며, 위와 같은 시작·종료 표식을 가집니다.
우리 예시에서는 파일 전체가 하나의 충돌입니다.

다음으로 첫 번째 섹션을 봅시다.

```
%%%%%%% Changes from base to side #1
 print("Hello, world!")
+print("Hallo, Welt!")
+print("Bonjour, le monde!")
```

헤더 "Changes from base to side #1"의 의미는 무엇일까요?
"base"는 두 브랜치가 갈라지기 시작한 커밋을 의미합니다.
로그에 보이는 "Merge code and documentation for hello-world" 커밋이 바로 base입니다.

side 번호는 우리가 머지 명령에서 지정한 순서에 대응합니다.
`jj new main @-`을 실행했으니 "side #1"은 `main` 브랜치에 해당합니다.

즉, 이 섹션은 `main` 브랜치에서 충돌된 줄이 어떻게 바뀌었는지 diff 형식으로 보여 줍니다.
공백은 변경 없음, `-`는 삭제, `+`는 추가를 의미합니다.
여기서는 영어 문장이 그대로이고, 독일어와 프랑스어 문장이 추가되었습니다.

두 번째 섹션을 봅시다.

```
+++++++ Contents of side #2
for _ in range(10):
    print("Hello, world!")
```

이 섹션은 "base 대비 side #2 변경"이 아니라, 단순히 side #2의 최종 상태를 보여 줍니다.
base 상태는 앞 섹션으로부터 유추할 수 있기 때문입니다.

설명이 다소 장황했지만, 실제 충돌은 훨씬 복잡할 수 있습니다.
이 정도 배경지식이 있다면 앞으로 충돌을 훨씬 잘 다룰 수 있을 것입니다.

## 충돌 해결하기

각 충돌 측면의 상태를 이해했으니, 어떻게 해결할까요?
여기에는 **기계적인 정답이 없습니다.**
기계적으로 해결할 수 있었다면 Jujutsu가 이미 해 주었을 테니까요.
머지 충돌의 핵심은, 변경의 의미에 따라 정답이 달라진다는 것입니다.

이번 충돌의 의미는 다음과 같습니다.
- 인사를 10번 반복하는 루프를 추가한다.
- 독일어와 프랑스어 인사도 출력한다.

머지 결과에서 독일어와 프랑스어 인사도 10번 반복해야 할까요?
모든 언어를 반복한다면 순서를 섞어야 할까요, 아니면 따로따로 출력해야 할까요?

예를 들어 세 가지 합리적인 해결이 있습니다.

1. 영어 인사만 반복한다.
    ```py
    for _ in range(10):
        print("Hello, world!")
    print("Hallo, Welt!")
    print("Bonjour, le monde!")
    ```

1. 모든 언어를 반복하며 서로 이어 출력한다.
    ```py
    for _ in range(10):
        print("Hello, world!")
        print("Hallo, Welt!")
        print("Bonjour, le monde!")
    ```

1. 모든 언어를 반복하되 각각 따로 반복한다.
    ```py
    for _ in range(10):
        print("Hello, world!")
    for _ in range(10):
        print("Hallo, Welt!")
    for _ in range(10):
        print("Bonjour, le monde!")
    ```

핵심은 충돌을 올바르게 해결하려면 약간의 사고가 필요하다는 사실입니다.

우리는 두 번째 옵션을 선택하겠습니다.
충돌 표식을 직접 편집해도 되고, 아래 명령으로 파일을 교체해도 됩니다.

```sh
echo 'for _ in range(10):
    print("Hello, world!")
    print("Hallo, Welt!")
    print("Bonjour, le monde!")' > hello.py
```

````admonish note title="충돌 해결을 도와주는 도구" collapsible=true
위에서는 충돌 표식을 원하는 결과로 직접 교체하는 방법을 설명했습니다.
이 수동 방식은 항상 통하지만 번거로울 수 있습니다.

상황에 따라 충돌 해결을 도와주는 도구가 여럿 있습니다.
예를 들어 내장 도구 `:ours`, `:theirs`는 한쪽 변경을 버리고 다른 쪽만 남기는 역할을 합니다.
어느 쪽이 "ours"이고 어느 쪽이 "theirs"인지 헷갈릴 수 있으니, 실행해 보고 마음에 들지 않으면 `jj undo`로 되돌리세요.

```sh
# 우리 쪽 변경만 유지하고 상대 쪽은 버리기
jj resolve --tool :ours
```

이런 단순 도구 외에도 [Mergiraf](https://mergiraf.org/)처럼 더 강력한 외부 도구도 사용할 수 있습니다.
Mergiraf는 충돌한 파일의 **구문 트리** 를 분석해 자동 해결을 시도합니다.
별도로 설치한 뒤 다음처럼 실행하면 됩니다.

```sh
jj resolve --tool mergiraf
```

Jujutsu에는 Mergiraf 호출 방법이 기본 설정으로 들어 있습니다.
다른 도구를 쓰고 싶다면 [사용자 정의 머지 도구 설정](https://jj-vcs.github.io/jj/latest/config/#3-way-merge-tools-for-conflict-resolution)을 추가하세요.
````
