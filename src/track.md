Alice는 새 노트북을 장만했습니다. 엄청 신난 상태죠.
그녀가 고른 것은 [Framework 노트북](https://frame.work/)입니다.
제조사가 의도적으로 수리를 어렵게 만드는 것에 지친 탓입니다.
Framework는 Linux 공식 지원도 제공하니 Alice에게 매우 중요합니다.
사용자를 존중하는 하드웨어와 소프트웨어의 조합이라 생각하죠.

문제는 이제 저장소 사본이 없다는 것입니다.
이전 컴퓨터에서 복사해 올 수도 있었겠지만, 어차피 다시 클론하면 되니 그러지 않았습니다.
Alice가 새로 저장소를 클론하는 상황을 시뮬레이션해 봅시다.

```sh
cd ~ # 삭제할 디렉터리 밖으로 이동
rm -rf ~/jj-tutorial/repo
jj git clone ~/jj-tutorial/remote ~/jj-tutorial/repo
cd ~/jj-tutorial/repo

# Alice 역할
jj config set --repo user.name "Alice"
jj config set --repo user.email "alice@local"
jj metaedit --update-author
```

문제가 두 가지 있습니다.
첫째, 독일어/프랑스어 버전의 "Hello, world!" 커밋이 없습니다.
사실 그 커밋을 푸시하지 않았기 때문에 Alice의 옛 노트북에만 있었고, 지금은 영영 사라졌습니다.
할 수 있는 일은 다시 만드는 것뿐입니다.

```sh
echo 'print("Hallo, Welt!")' >> hello.py
echo 'print("Bonjour, le monde!")' >> hello.py
jj commit -m "Print German and French grettings as well"
```

커밋은 항상 푸시해야 한다는 교훈을 잊지 마세요!
푸시하지 않으면 원격은 백업 역할을 못합니다.
이번 커밋은 바로 `main` 북마크로 푸시할 수 있습니다.

```sh
jj bookmark move main -t @-
jj git push
```

둘째 문제는 루프 실험 커밋이 보이지 않는다는 점입니다.
이 커밋은 자동 생성 북마크와 함께 원격에 푸시했으므로 실제로 사라지지 않았습니다.
단지 기본적으로 숨겨져 있을 뿐이죠. `jj log --revisions 'all()'`로 찾을 수 있습니다.
