# 북마크 업데이트

````admonish reset title="진행 상황 초기화" collapsible=true
이 장의 시작으로 되돌리려면 다음 명령을 실행하세요.

```sh
curl https://jj-for-everyone.github.io/reset.sh | bash -s update_bookmark
cd ~/jj-tutorial/repo
```
````

새 북마크를 처음으로 원격에 푸시하는 방법을 배웠습니다.
만드는 모든 커밋마다 원격에 푸시할 북마크를 새로 만들 수도 있습니다.
하지만 그러면 필요 없는 북마크가 끝없이 쌓여 엉망이 되겠죠!

다행히 더 나은 방법이 있습니다.
북마크를 매번 새로 만드는 대신, 기존 북마크를 **다른 커밋으로 옮기면** 됩니다.

이를 시험해 보려면 먼저 새 커밋을 만들어야 합니다.
다음 명령을 그대로 복사해 실행하세요.

```sh
printf "\nThis is a toy repository for learning Jujutsu.\n" >> README.md
jj commit -m "Add project description to readme"
```

위 명령에는 재미있는 요령이 숨어 있습니다.
짧은 설명이 이미 떠올랐다면 `-m` 플래그(`--message`의 줄임)를 붙여 `jj commit`에 직접 넘길 수 있습니다.
별도의 텍스트 편집기를 여는 것보다 빠를 때가 많습니다.

`jj log`를 실행하면 원격으로 푸시했던 커밋 위에 새 커밋이 생긴 것을 볼 수 있습니다.

이제 북마크를 새 커밋을 가리키게 옮긴 다음 다시 푸시하면 원격으로 보낼 수 있습니다.
먼저 북마크를 옮겨 보겠습니다.

```sh
jj bookmark move main --to @-
```

change ID(`--to kxqyrwux`)를 사용해 이동할 위치를 명시할 수도 있었겠지만, 대신 `@-`를 사용했습니다.
이 표기법은 **워킹 카피 커밋의 부모** 를 가리키는 간단한 방법입니다.
커밋을 가리키는 영리한 표현은 많지만, 그 이야기는 나중으로 미룹니다.
지금은 `@-`만 기억하세요. 가장 자주 쓰이는 표기입니다.

중요한 점은 Jujutsu가 로컬 북마크 `main`과 원격에 있는 대응 관계의 불일치를 보여 준다는 것입니다.
`main*`은 로컬 북마크인데, 이름 옆의 별표는 원격과 동기화되지 않았다는 뜻입니다.
`main@origin`은 원격에 있는 북마크의 위치입니다.

이제 북마크를 다시 푸시해 상황을 해결할 수 있습니다.

```sh
jj git push
```

이번에는 `--bookmark main`을 명시하지 않았습니다.
`push` 명령에서 `--bookmark` 플래그를 생략하면 Jujutsu가 실제로 푸시하고 싶은 북마크를 똑똑하게 추려 줍니다.
대부분의 경우 잘 동작합니다.
원하는 대로 되지 않았다면 `--bookmark` 플래그를 붙여 다시 시도하세요.

이쯤에서 이런 의문이 들 수 있습니다.
원격은 커밋을 받으려면 북마크가 필요하고, `main` 북마크는 더 이상 첫 번째 커밋을 가리키지 않는데... 그 커밋은 이제 잃어버린 걸까요?
다행히 그렇지 않습니다.
커밋은 부모 커밋을 가리키는 참조를 저장합니다.
그래서 Jujutsu가 `jj log` 출력에서 커밋을 순서대로 그릴 수 있는 것입니다.
이 참조들이 체인을 이루어 북마크가 붙은 커밋의 모든 조상을 보호해 줍니다.
